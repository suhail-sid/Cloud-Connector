🔑 Key Concepts Explained

GitHub PAT (Personal Access Token)

  • PAT = A secure password-like token for API authentication
  • Like a special key that proves you are a valid GitHub user
  • Safer than using your actual GitHub password
  • Can be revoked anytime if compromised

How we use it

Store in .env file (never share it) → API uses it for authenticated requests → GitHub trusts requests with valid PAT

REST API

REST = Representational State Transfer — a web standard using HTTP methods (GET, POST, DELETE, PUT), URL endpoints, and JSON responses.

GET  /repos/user/octocat         → Fetch octocat's repositories
POST /issues/octocat/Hello-World  → Create issue
GET  /health                      → Check if API is working

When you run python main.py, you get three documentation URLs:

2️⃣ ReDoc — /redoc

http://localhost:8000/redoc

Alternative, more formal documentation viewer. Better for reading documentation, organized in columns. Can't test endpoints from here.

3️⃣ OpenAPI JSON — /openapi.json

http://localhost:8000/openapi.json

Machine-readable API specification in OpenAPI/Swagger format. This is what Swagger UI and ReDoc consume.

Architecture Explanation (2 min)

main.py              → FastAPI application with endpoints
github_client.py     → GitHub API client (handles all API calls)
config.py            → Configuration management (loads .env file)
models.py            → Pydantic models (validates requests/responses)
exceptions.py        → Custom exceptions (proper error handling)

Request Flow

1

User makes request → http://localhost:8000/repos/user/torvalds

2

FastAPI receives it → main.py endpoint handler

3

Validates input → models.py checks data types

4

Calls GitHub client → github_client.py makes HTTP request

5

GitHub returns data → Client receives response

6

Returns to user → As JSON response

🔍 Endpoint Deep Dive

GET/health

Purpose: Verify API is working and authenticated
Response: {"status":"healthy","authenticated":true,"user":"your_username"}
Use Case: Monitoring, status checks

GET/user

Purpose: Fetch your GitHub profile info
Response: Profile data (username, bio, followers, etc.)
Use Case: Verify authentication, get user info

GET/repos/user/{username}

Purpose: List all repositories of a GitHub user
Params: username, per_page (1-100)
Example: GET /repos/user/torvalds?per_page=10

GET/repos/org/{org_name}

Purpose: List all repos of a GitHub organization
Params: org_name, per_page (1-100)
Example: GET /repos/org/facebook?per_page=5

GET/issues/{owner}/{repo}

Purpose: Get all issues from a repository
Params: owner, repo, state (open/closed/all), per_page
Example: GET /issues/facebook/react?state=open&per_page=10

POST/issues/{owner}/{repo}

Purpose: Create a new issue in a repository

{ "title": "Bug: Login button", "body": "When I click login, nothing happens", "labels": ["bug"] }
GET/commits/{owner}/{repo}

Purpose: List commits from a repository
Params: owner, repo, per_page
Example: GET /commits/torvalds/linux?per_page=5
